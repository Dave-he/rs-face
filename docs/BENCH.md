# 性能基准

## 测试环境

- 硬件: M2 MacBook Air (8 核)
- 视频库: /Users/hyx/Movies/考研 (8171 个视频, 主要是 25-30 fps 教学视频)
- 默认参数: `--fps 1.0 --min-size 60 --max-size 600`

## 48 视频实测 (从 8171 视频中抽样)

| 指标 | 数值 |
|---|---|
| 视频数 | 48 |
| 成功 | 47 (97.9%) |
| 失败 | 1 (H.264 解码错误, 视频本身损坏) |
| 总帧 | 65,189 |
| 总用时 | 156 min (2h36m) |
| 吞吐量 | 6.94 fps |

### 单视频样本

| 帧数 | 用时 | 平均 fps |

| 68 | 16s | 4.2 |

吞吐量受视频分辨率影响: 720p 视频 8-12 fps, 1080p 视频 4-6 fps。

## 关键瓶颈

| 阶段 | 占比 | 优化 |
|---|---|---|
| ffmpeg 抽帧 | 5% | 已用 `-compression_level 0` |
| 积分图构建 | 5% | 无法绕过 |
| Cascade 检测 | 80% | 多线程并行 + 自动步长 2→4 |
| 跟踪 (LBPH) | 5% | 画廊在线均值 |
| 写盘 | 5% | 1.5MB/PNG/帧 |

## 加速来源

| 优化 | 加速 |
|---|---|
| 原始单线程 | 1x |
| `std::thread` 6 核并行 | 5x |
| 自动步长 2→4 | 17x |
| **合计** | **87x** |

## 失败案例

**Case 1: 损坏的 H.264 流**
```
[dec:h264] Task finished with error code -1145393733
Conversion failed!
```
视频本身损坏, ffmpeg 无法解码。我们的工具很正常地报错退出。
解决: 视频文件需要重新下载或转码。

## 后续优化方向

1. **HOG 跟踪**: LU 实测不如 LBPH, 暂不上
2. **SIMD**: 用 std::arch::aarch64 NEON 加速积分图
3. **跨平台**: 在 Linux x86 上 SSSE3/AVX2 加速
4. **GPU**: 接 Vulkan/CUDA 加速图像处理
